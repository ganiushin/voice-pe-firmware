# Changelog

## 26.6.0.4

Исправления по проверке 16.10.2026.

* Лог объявления печатал текст как C-строку, а `msg.text` — `StringRef` без завершающего нуля:
  чтение за концом буфера (в логе — байты звука после текста). Вероятная причина падения
  `LoadProhibited`. Теперь печатается ровно длина строки.
* `TTS_STREAM_START` принимается только в ожидании ответа или во время него. Отказанное объявление
  или ответ, который уже остановили, больше не включают динамик посреди разговора или в простое;
  звук после `TTS_STREAM_END` отбрасывается.
* Обратный отсчёт на кольце строится по первому *активному* таймеру: застрявший неактивный таймер
  на 0 с больше не гасит кольцо для всех следующих.
* «Стоп стоп», «Стоп, стоп!» в продолжении разговора тоже завершают его.
* Кнопка: колонка начинает слушать, когда звук нажатия доиграл (как после слова пробуждения),
  а не через фиксированные 300 мс — звук нажатия не попадает в запись.

## 26.6.0.3

Колонка говорит по инициативе агента: «Таймер «паста» закончился», напоминания.

* Объявление (`VoiceAssistantAnnounceRequest`) в режиме «ответ через динамик»: колонка готовится
  принять звук, клиент присылает его PCM по API (`TTS_STREAM_START`, звук, `TTS_STREAM_END`), как ответ.
  Когда последний сэмпл доигран, колонка отвечает `AnnounceFinished`; занята разговором — сразу
  отвечает отказом, клиент повторяет позже.
* Объявление не теряется после прерванного разговора: фильтр «событий прерванного разговора»
  сбрасывается, буфер звука выделяется заново.
* Слово пробуждения или кнопка обрывают объявление; `start_conversation` — после объявления колонка слушает.
* Если поток не начался за 10 с, объявление отменяется.

## 26.6.0.2

Ответ ассистента идёт сырым PCM по ESPHome API прямо в динамик, без медиаплеера и ссылок.
Сделано для [home-agent](https://github.com/ganiushin/home-agent): агент сам подключается к колонке
вместо Home Assistant. С конвейером Assist в Home Assistant эта версия не проверялась.

* `voice_assistant` выводит ответ в отдельный вход микшера (`va_resampling_speaker`), а не через медиаплеер.
  Нет скачивания по ссылке, буферизации 250 КБ и зависания, если ссылка не открылась.
* `TTS_STREAM_START` задаёт формат потока (`sample_rate`, `channels`), запускает динамик и сразу переводит
  колонку в режим ответа: звук играет, пока агент ещё генерирует текст. По умолчанию — 16 кГц моно.
* Буфер приёма ответа увеличен до 64 КБ (~0,7 с при 48 кГц).
* После конца потока динамик доигрывает остаток и останавливается сразу, без 5-секундного таймера:
  в режиме диалога колонка начинает слушать сразу после последнего слова.
* Слово пробуждения или кнопка во время ответа обрывают его и просят агента прекратить отправку;
  звук, который ещё в пути, отбрасывается.
* Ключ API по-прежнему выдаёт клиент при первом подключении (`encryption:` без ключа).

## 26.6.0.1

Первый релиз. Основа: Voice PE 26.6.0, компоненты ESPHome 2026.9.0.

* Микрофон в режиме диалога открывается только после того, как ответ реально доигран до DAC, а не через 2 секунды после отправки ссылки.
* Слово пробуждения во время ответа или ожидания продолжения прерывает колонку и сразу начинает слушать.
* «Stop» работает весь разговор. В продолжении разговора распознанные «stop» или «стоп» завершают его до ответа агента.
* Колонка начинает слушать после того, как звук пробуждения доиграл. Сам звук укорочен до 350 мс.
* Исправлено в `speaker_source`: `stop` во время буферизации, зависание плейлиста при ошибке источника.
* Обновления из релизов этой репы, установка из браузера на GitHub Pages.
* Настройка «Voice processing»: какая обработка XMOS применяется к звуку, который уходит в STT (полная, без AGC, только эхоподавление).

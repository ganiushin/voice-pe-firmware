# Voice PE: диалог без самопрослушивания

Прошивка для Home Assistant Voice PE. Колонка больше не слышит собственный ответ в режиме продолжения разговора.

Основа: пакет [home-assistant-voice-pe 26.6.0](https://github.com/esphome/home-assistant-voice-pe/tree/26.6.0)
и компоненты `speaker_source` и `voice_assistant` из [ESPHome 2026.9.0](https://github.com/esphome/esphome/tree/2026.9.0).

## Проблема

В стоковой прошивке `voice_assistant` ставит таймер на 2 секунды, когда отдаёт медиаплееру ссылку на ответ.
Если плеер за это время не начал воспроизведение (Voice PE сначала набирает буфер 250 кБ), ответ считается законченным.
В режиме диалога микрофон открывается раньше, чем колонка начинает говорить, и ответ попадает в распознавание.
Подробнее: [esphome/home-assistant-voice-pe#563](https://github.com/esphome/home-assistant-voice-pe/issues/563),
[#621](https://github.com/esphome/home-assistant-voice-pe/issues/621), [esphome/esphome#16512](https://github.com/esphome/esphome/pull/16512).

## Как работает исправление

Микрофон открывается по событию, а не по таймеру.

* `speaker_source` сообщает событие «объявление завершено» с результатом `completed`, `stopped` или `failed`.
  Событие отправляется, когда выполнены все условия:
  * очередь команд пуста;
  * плейлист объявлений закончился;
  * ни один источник не играет и не запускается;
  * все отправленные в динамик сэмплы реально ушли в DAC. Это считается по колбэкам воспроизведения `i2s → mixer → resampler`.
* `voice_assistant` ждёт это событие; своих таймеров и опроса состояния плеера у него нет.
  * `completed`: если ответ был вопросом, открывается микрофон.
  * `stopped` или `failed`: разговор завершается, микрофон не открывается.
* Условие `speaker_source.is_announcement_active` истинно от запроса звука до ухода последнего сэмпла в DAC.
  По нему колонка начинает слушать после звука пробуждения (вместо `delay: 300ms`)
  и после прерванного ответа.
* Звук пробуждения укорочен до 350 мс ([`sounds/wake_word_triggered_short.flac`](sounds/wake_word_triggered_short.flac)).
  В стоковом файле (947 мс) после самого сигнала идёт ~0,7 с тихого реверба и тишины,
  а слушать колонка начинает только после конца файла.
* Попутно исправлено в `speaker_source`:
  * `stop` во время буферизации раньше не останавливал источник, и ответ начинал играть после остановки;
  * ошибка источника раньше навсегда подвешивала плейлист объявлений.

Защитные таймеры (срабатывают, только если событие потерялось):

| Где | Значение | Что делает |
|---|---|---|
| `speaker_source.announcement_start_timeout` | 30 с | Объявление так и не начало играть: оно останавливается, результат `failed`, разговор завершается |
| слив хвоста в `speaker_source` | длительность недоигранных сэмплов + 500 мс | Счётчик сэмплов разошёлся: событие отправляется с предупреждением в логе |
| ожидание тишины при перебивании и после звука пробуждения | 5 с | Не даёт автоматизации зависнуть |

## Поведение

| Ситуация | Что происходит |
|---|---|
| Ответ заканчивается вопросом | Колонка договаривает до последнего сэмпла, затем слушает |
| Ответ без вопроса | Договаривает и замолкает |
| Во время ответа или ожидания продолжения сказали «Stop» | Всё останавливается, разговор завершён |
| Во время ответа или ожидания продолжения сказали слово пробуждения | Ответ прерывается, колонка сразу слушает новый вопрос (контекст разговора сохраняется) |
| В продолжении разговора распознано только «stop» или «стоп» | Разговор завершается до ответа агента (страховка на случай, если модель «Stop» не сработала) |
| Во время ответа говорят что-то другое | Игнорируется |
| Ответ не удалось воспроизвести | Разговор завершается |

Модель `stop` английская, срабатывает на слово «Stop». Она включена от начала первого ответа до конца разговора.
Фразы-страховки для распознанного текста задаются подстановкой `stop_phrases`.

## Установка

Отдельный аддон не нужен. После прошивки колонка остаётся в Home Assistant той же:
* имя остаётся `home-assistant-voice-XXXXXX`;
* ключ API — тот, что HA уже записал на колонку;
* Wi-Fi берётся из памяти колонки;
* improv по BLE и USB сохранён.

Обновления приходят из релизов этой репы: в HA у колонки есть сущность обновления,
которая проверяет [манифест на GitHub Pages](https://ganiushin.github.io/voice-pe-firmware/firmware/manifest.json).
Чтобы вернуться на сток, прошейте его через [установщик Voice PE](https://esphome.github.io/home-assistant-voice-pe/).

### Вариант 1: из браузера по USB
Откройте https://ganiushin.github.io/voice-pe-firmware/ в Chrome или Edge и нажмите «Установить».
Нужна только первая прошивка, дальше колонка обновляется из HA.

### Вариант 2: ESPHome Device Builder
Создайте устройство с содержимым [`example/voice-pe.yaml`](example/voice-pe.yaml) и нажмите Install → Wirelessly.
Номер релиза указывается в двух местах, они должны совпадать:

```yaml
substitutions:
  voice_pe_components_source: github://ganiushin/voice-pe-firmware@26.6.0.1

packages:
  voice_pe: github://ganiushin/voice-pe-firmware/home-assistant-voice.factory.yaml@26.6.0.1
```

Прошивка, собранная в Device Builder, называется `dev`, поэтому HA будет предлагать обновиться до последнего релиза.

### Вариант 3: из локальной копии
```bash
uv venv -p 3.13 .venv && uv pip install -p .venv esphome==2026.9.0
.venv/bin/esphome run home-assistant-voice.factory.yaml --device /dev/cu.usbmodem101        # по USB
.venv/bin/esphome run home-assistant-voice.factory.yaml --device home-assistant-voice-XXXXXX.local   # по сети
```
Стоковая прошивка принимает OTA без пароля.

## Версии и релизы

Версия — это `<версия Voice PE, от которой сделана прошивка>.<номер>`, например `26.6.0.1`.
Изменения по версиям описаны в [CHANGELOG.md](CHANGELOG.md).

Как выпустить релиз:
1. Обновить `CHANGELOG.md`, номер релиза в `example/voice-pe.yaml` и в README.
2. Создать релиз с тегом новой версии:
   `gh release create 26.6.0.2 --title 26.6.0.2 --notes-file <описание>`.
3. CI ([`build.yml`](.github/workflows/build.yml)) соберёт прошивку, приложит бинарники к релизу
   и опубликует её на GitHub Pages. После этого HA покажет обновление.

Каждый пуш в `main` и каждый PR тоже собирается в CI, прошивку можно скачать из артефактов сборки.

## Структура

* `home-assistant-voice.factory.yaml`: полный конфиг устройства (стоковый factory с обновлениями из этой репы).
* `home-assistant-voice.yaml`: пакет Voice PE с изменениями.
* `components/`: изменённые `speaker_source` и `voice_assistant`.
* `sounds/`: укороченный звук пробуждения.
* `static/`: страница установки из браузера.
* `upstream/`: нетронутые исходники, от которых сделаны изменения.
  Посмотреть все правки: `diff -ru upstream/esphome-2026.9.0 components` и
  `diff -u upstream/home-assistant-voice-pe-26.6.0/home-assistant-voice.yaml home-assistant-voice.yaml`.

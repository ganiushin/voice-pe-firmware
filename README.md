# Voice PE: диалог без самопрослушивания

Прошивка для Home Assistant Voice PE. Колонка больше не слышит собственный ответ в режиме продолжения разговора.

Основа: пакет [home-assistant-voice-pe 26.6.0](https://github.com/esphome/home-assistant-voice-pe/tree/26.6.0)
и компоненты `speaker_source` и `voice_assistant` из [ESPHome 2026.9.0](https://github.com/esphome/esphome/tree/2026.9.0).

## Проблема

В стоковой прошивке `voice_assistant` ставит таймер на 2 секунды, когда отдаёт медиаплееру ссылку на ответ.
Если плеер за это время не начал воспроизведение (Voice PE сначала набирает буфер 250 кБ), ответ считается законченным.
В режиме диалога микрофон открывается раньше, чем колонка начинает говорить, и ответ попадает в распознавание.
Подробнее: [esphome/home-assistant-voice-pe#563](https://github.com/esphome/home-assistant-voice-pe/issues/563),
[#621](https://github.com/esphome/home-assistant-voice-pe/issues/621), [esphome/esphome#16512](https://github.com/esphome/esphome/pull/16512).

## Как работает исправление

Микрофон открывается по событию, а не по таймеру.

* `speaker_source` сообщает событие «объявление завершено» с результатом `completed`, `stopped` или `failed`.
  Событие отправляется, когда выполнены все условия:
  * очередь команд пуста;
  * плейлист объявлений закончился;
  * ни один источник не играет и не запускается;
  * все отправленные в динамик сэмплы реально ушли в DAC. Это считается по колбэкам воспроизведения `i2s → mixer → resampler`.
* `voice_assistant` ждёт это событие.
  * `completed`: если ответ был вопросом, открывается микрофон.
  * `stopped` или `failed`: разговор завершается, микрофон не открывается.
* Попутно исправлено в `speaker_source`:
  * `stop` во время буферизации раньше не останавливал источник, и ответ начинал играть после остановки;
  * ошибка источника раньше навсегда подвешивала плейлист объявлений.

Защитные таймеры (срабатывают, только если событие потерялось):

| Где | Значение | Что делает |
|---|---|---|
| `voice_assistant.response_start_timeout` | 30 с | Ответ так и не начал играть: разговор завершается, объявление останавливается |
| слив хвоста в `speaker_source` | длительность недоигранных сэмплов + 500 мс | Счётчик сэмплов разошёлся: событие отправляется с предупреждением в логе |
| ожидание тишины при перебивании словом пробуждения | 5 с | Не даёт автоматизации зависнуть |

## Поведение

| Ситуация | Что происходит |
|---|---|
| Ответ заканчивается вопросом | Колонка договаривает до последнего сэмпла, затем слушает |
| Ответ без вопроса | Договаривает и замолкает |
| Во время ответа или ожидания продолжения сказали «Stop» | Всё останавливается, разговор завершён |
| Во время ответа или ожидания продолжения сказали слово пробуждения | Ответ прерывается, колонка сразу слушает новый вопрос (контекст разговора сохраняется) |
| Во время ответа говорят что-то другое | Игнорируется |
| Ответ не удалось воспроизвести | Разговор завершается |

Модель `stop` английская, срабатывает на слово «Stop». Она включена от начала первого ответа до конца разговора.

## Установка

В ESPHome Device Builder замените конфиг вашей Voice PE содержимым [`example/voice-pe.yaml`](example/voice-pe.yaml).
Ключ API и Wi-Fi оставьте свои. Нужен ESPHome 2026.9.0 или новее.

```yaml
packages:
  voice_pe: github://ganiushin/voice-pe-firmware/home-assistant-voice.yaml@main
```

Компоненты скопированы из ESPHome 2026.9.0. На другой версии ESPHome сборка может не пройти, и их придётся перенести на новую версию.

## Локальная сборка

```bash
uv venv -p 3.13 .venv && uv pip install -p .venv esphome==2026.9.0
cp test/secrets.example.yaml test/secrets.yaml   # заполнить
.venv/bin/esphome compile test/local-build.yaml
```

## Структура

* `home-assistant-voice.yaml`: пакет Voice PE с изменениями.
* `components/`: изменённые `speaker_source` и `voice_assistant`.
* `upstream/`: нетронутые исходники, от которых сделаны изменения.
  Посмотреть все правки: `diff -ru upstream/esphome-2026.9.0 components` и
  `diff -u upstream/home-assistant-voice-pe-26.6.0/home-assistant-voice.yaml home-assistant-voice.yaml`.

# Voice PE для home-agent

Прошивка для Home Assistant Voice PE, в которой колонка — голосовой интерфейс
[home-agent](https://github.com/ganiushin/home-agent). В Home Assistant колонки нет: агент сам подключается
к ней по ESPHome API, выдаёт ей ключ, принимает звук с микрофона и отвечает звуком прямо в динамик.

Основа: пакет [home-assistant-voice-pe 26.6.0](https://github.com/esphome/home-assistant-voice-pe/tree/26.6.0)
и компоненты `speaker_source` и `voice_assistant` из [ESPHome 2026.9.0](https://github.com/esphome/esphome/tree/2026.9.0).

## Установка

1. Откройте https://ganiushin.github.io/voice-pe-firmware/ в Chrome или Edge, подключите колонку по USB
   и нажмите «Установить». Там же установщик подключит колонку к Wi-Fi (improv).
2. В агенте откройте «Настройки» → «Добавить колонку», введите её IP и комнату.
   Агент выдаст колонке свой ключ API; с другими клиентами она больше не заговорит.
3. Обновления приходят из релизов этой репы: агент показывает новую версию в карточке колонки
   и ставит её по кнопке (колонка забирает прошивку из [манифеста на GitHub Pages](https://ganiushin.github.io/voice-pe-firmware/firmware/manifest.json)).

Если колонку удалить в агенте, он сотрёт на ней ключ, и её можно добавить заново.
Чтобы вернуться на сток, прошейте его через [установщик Voice PE](https://esphome.github.io/home-assistant-voice-pe/).

Из локальной копии:

```bash
uv venv -p 3.13 .venv && uv pip install -p .venv esphome==2026.9.0
.venv/bin/esphome run home-assistant-voice.factory.yaml --device /dev/cu.usbmodem101        # по USB
.venv/bin/esphome run home-assistant-voice.factory.yaml --device home-assistant-voice-XXXXXX.local   # по сети
```

Прошивка принимает OTA без пароля, как стоковая. Локальная сборка получает версию `0.0.0-local`,
поэтому агент предложит обновиться до последнего релиза.

## Как отвечает колонка

Ответ приходит сырым PCM по ESPHome API и сразу идёт в динамик через отдельный вход микшера:
`TTS_STREAM_START` (частота и число каналов), куски звука, `TTS_STREAM_END`. Звук играет, пока агент
ещё генерирует текст. Медиаплеер и ссылки для ответа не нужны; плеер остаётся для звуков колонки и музыки.

* Буфер приёма — 64 КБ (~0,7 с при 48 кГц); всё, что не влезло, колонка выбрасывает, поэтому агент
  отправляет звук в темпе воспроизведения.
* После конца потока динамик доигрывает остаток и останавливается сразу, без таймера: в режиме диалога
  колонка начинает слушать сразу после последнего слова, а не во время него.
* Слово пробуждения или кнопка во время ответа обрывают его и говорят агенту прекратить отправку.

Конец фразы определяет агент (VAD), а не колонка; настраивается в агенте для каждой колонки.

## Поведение

| Ситуация | Что происходит |
|---|---|
| Ответ заканчивается вопросом | Колонка договаривает до последнего сэмпла, затем слушает |
| Ответ без вопроса | Договаривает и замолкает |
| Во время ответа или ожидания продолжения сказали «Stop» | Всё останавливается, разговор завершён |
| Во время ответа или ожидания продолжения сказали слово пробуждения | Ответ прерывается, колонка сразу слушает новый вопрос (контекст разговора сохраняется) |
| В продолжении разговора распознано только «stop» или «стоп» | Разговор завершается до ответа агента (страховка на случай, если модель «Stop» не сработала) |
| Во время ответа говорят что-то другое | Игнорируется |

«Обработка звука для распознавания» в настройках колонки выбирает, какой звук уходит в распознавание:
полная обработка XMOS (эхоподавление, подавление помех, шумоподавление, AGC), без AGC или только эхоподавление.

Модель `stop` английская, срабатывает на слово «Stop». Она включена от начала первого ответа до конца разговора.
Фразы-страховки для распознанного текста задаются подстановкой `stop_phrases`.

Звук пробуждения укорочен до 350 мс ([`sounds/wake_word_triggered_short.flac`](sounds/wake_word_triggered_short.flac)):
в стоковом файле после сигнала ~0,7 с тишины, а слушать колонка начинает только после конца файла. Конец звука
пробуждения колонка узнаёт по событию `speaker_source` «объявление завершено» — когда последний сэмпл ушёл в DAC.

## Версии и релизы

Версия — это `<версия Voice PE, от которой сделана прошивка>.<номер>`, например `26.6.0.2`.
Изменения по версиям описаны в [CHANGELOG.md](CHANGELOG.md).

Как выпустить релиз:
1. Обновить `CHANGELOG.md`.
2. Создать релиз с тегом новой версии:
   `gh release create 26.6.0.3 --title 26.6.0.3 --notes-file <описание>`.
3. CI ([`build.yml`](.github/workflows/build.yml)) соберёт прошивку, приложит бинарники к релизу
   и опубликует её на GitHub Pages. После этого агент покажет обновление.

Каждый пуш в `main` и каждый PR тоже собирается в CI (версия `0.0.0-ci.<номер сборки>`), прошивку можно скачать из артефактов сборки.
Версию `dev` использовать нельзя: она считается новее любого релиза, и обновление не предложится.

## Структура

* `home-assistant-voice.factory.yaml`: полный конфиг устройства (стоковый factory: improv по BLE и USB, обновления из этой репы).
* `home-assistant-voice.yaml`: пакет Voice PE с изменениями.
* `components/`: изменённые `speaker_source` и `voice_assistant`.
* `sounds/`: укороченный звук пробуждения.
* `static/`: страница установки из браузера.
* `upstream/`: нетронутые исходники, от которых сделаны изменения.
  Посмотреть все правки: `diff -ru upstream/esphome-2026.9.0 components` и
  `diff -u upstream/home-assistant-voice-pe-26.6.0/home-assistant-voice.yaml home-assistant-voice.yaml`.
